# 标贝全量后端基准

固定评测 BZNSYP **10,000 句**，主报告只有一个 `report.json`，记录后端配置、切分指标和性能。
不再生成 Markdown 报告。命令标准输出仅返回 JSON 路径，进度写到标准错误。
不需要手写临时评测器、准备阈值子集、安装 PyTorch 或导出另一份模型。
需要 Node.js 24+、Python 3.9+，支持当前 macOS/Linux 开发环境。

这是按需启动的评估工具，不是每次 Git 提交的强制步骤。仅请求提交已验证的改动时，
复用适用的已有检查结果，不自动重复耗时的全量基准。

## 一行命令

在 **haodu 根目录**：

```sh
npm run golden:benchmark
```

脚本和评分实现位于本仓库的 `benchmark/`。默认读取本仓库
`src/boundary-model-data.js` 和 `src/backend/{chunker,inference}.js` 的当前工作区代码，
不依赖 training 仓库、checkpoint、训练清单或 PyTorch。
本地题库为 `benchmark/golden/cases.csv`，官方来源与固定哈希见
[题库说明](../benchmark/golden/README.md)。新克隆先从官方取得标注文本，再执行：

```sh
npm run golden:import -- --source /path/to/000001-010000.txt
```

CSV 和生成结果均被 Git 忽略，不随公开代码或扩展包分发。缺少数据时明确报错并给出导入命令。

训练仓库负责训练、验证和导出。要测试某个研究模型，直接在本仓库指定导出文件：

```sh
npm run golden:benchmark -- --model /path/to/export.js --output /path/to/results
```

`--model` 或替代 `--backend-dir` 必须配合独立 `--output`，避免混入默认基线。
每次命令只运行所选的一套后端和一个模型，不会额外运行另一版本，也不自动导出权重。
`target: public` 表示本仓库默认模型/后端；自定义输入记为 `custom`。这些是来源标签，不是发布版本号。

后端阈值、置信度、预处理和递归都直接使用实际代码默认值，不替换源码常量。
目前默认是至少 13 个视觉单位、置信度严格大于 0.45；将来代码变更会自然体现在同一测试中。
实验门控尚未接入公开后端，因此此入口不会自动加入门控。

## 固定题面与评分

- CSV 字节必须匹配 `benchmark/golden/source.json` 的 SHA-256，ID 必须完整、有序地覆盖 `000001`～`010000`。
- 沿用 `bznsyp_golden.project`：删除 #2/#3 紧邻的连续 proxy，保留其余文字、标点和引号，使用 UTF-16 坐标。
- 不按长度、后端可切性、同文或已知错标筛题；包括 `003892`，与之前全量比较的 10,000 句分母一致。
- #3 必切，#2 可选；同一中文右双引号两侧按一对一匹配视为等价，不能重复得分。
- 整句正确要求没有错切且没有漏掉 #3。Precision 为命中的 #2/#3 数除以全部预测；Recall 为命中的 #3 数除以全部 #3。
- F1 按用户自定义口径计算：`2 * precision * recall / (precision + recall)`，沿用上述 P/R 定义。
  P/R 任一未定义时为 `null`；二者均为 0 时 F1 为 0。各比率使用 0～1 数值。

训练方案和模型的改进用这份固定题集评估，不将它加入训练数据，也不按预测调整答案。
它已经被反复研究，属于固定开发评测集，不宣称为独立盲测。

## 性能口径

使用实际 JavaScript 推理实现和 `HaoduChunker.process([text])`。默认固定 **8 个 Node 进程**，
按原始题目索引 `index % 8` 分片，各负责 1,250 句；每个进程内按原始顺序逐句执行。
分片不依赖模型、答案或预测结果。可用 `--workers N` 明确改进程数；不会按机器负载自动改变。

每个进程从自己的分片按固定间隔取 100 句预热，共 800 次。所有进程预热完成才开始计时。
完整执行 **2 轮，共 20,000 次**：轮内并行，轮间串行，上一轮所有分片结束才启动下一轮。
每轮重新推理，脚本不缓存 logits 或预测；两轮逐题切点必须完全一致，否则运行失败。
最终按原始 ID 顺序合并结果，验证无缺题、重复或乱序。

| 指标 | 含义 |
|---|---|
| `batch_wall_ms` | 每轮向全部进程发出开始指令，到最后一个进程报告完成的实际等待时间，两轮取算术平均值；主要速度指标 |
| `backend_total_ms` | 全部进程每轮 10,000 次 process 调用耗时之和，两轮取算术平均值；含预处理、词语保护、递归和模型，**不是整轮等待时间** |
| `model_total_ms` | 全部进程每轮实际 scoreTokens 调用耗时之和，两轮取算术平均值；排除前后处理，也不是整轮等待时间 |
| `sentences_per_second` | 各轮 10,000 / `batch_wall_ms` 秒数的算术平均值 |
| `backend_sentence_ms` | 全部 20,000 次后端调用在固定并发负载下的 mean、p50、p95、p99，分位数采用 nearest-rank |
| `model_sentence_ms` | 每句所有递归模型调用的累计耗时分布；跳过推理的题为 0 |
| `startup_wall_ms` | 进程创建、模型加载和预热到全部就绪的实际时间，不计入批次速度 |
| `load_ms` / `warmup_ms` | 各进程加载 / 预热耗时的最大值；各进程阶段可能交错，不等同于整体启动时间 |
| `passes` | 每轮实际等待时间、累计计算时间、CPU 时间、调用数、token 数、吞吐和各分片测量值 |

`batch_wall_ms` 包含开始/完成消息传递、逐句输出校验和进度日志的开销；进程启动、模型加载、
预热、最终详细结果传输、评分、报告读写均在其外。累计后端/模型调用计时则不包含校验与日志。
保留原始两轮数值，汇总取算术平均值，不取最快轮次，也不将多个进程的耗时之和冒充等待时间。

少递归可能降低模型累计耗时，不能仅据此断言网络本身更快，因此同时保留调用数与 token 数。
这测的是固定并发下 Node CPU 后端的批量处理能力，不代表单进程延迟，也不包含浏览器 DOM、
worker 通信、绘制或页面加载。对比速度时使用相同进程数、分片、预热、机器、Node/V8/ICU、
系统和启动选项，避免并行训练或其他重负载；相同进程数也不能消除其他系统负载带来的波动。

## 基线与回归

首次成功运行自动固定基线；以后每次运行都对比该基线，**不会随运行滚动覆盖**。
每次结果在独立目录保留；只有明确接受新的行为或性能后再执行：

```sh
npm run golden:benchmark -- --set-baseline
```

这个命令仍会完整测量，并保留与旧基线的差异；它代表显式接受新基线，不是规避失败的重试参数。
基线报告和逐句结果都校验哈希。一个输出目录同时只允许一次运行；中断、输入中途变化、输出不完整或异常都不更新基线/latest。

整句正确率、Precision、Recall 任一个下降会标记质量回归。
批次等待时间、累计后端或模型平均耗时上升 **超过 5%** 会标记性能回归，这是控制波动的默认容差，不是统计显著性声明。
需要调整时使用 `--slowdown-percent 10`；报告记录实际容差。
数据/评分变化时不声称质量可比；机器、运行环境或测量协议变化时不声称速度可比。
模型或后端源码改变是本测试的比较对象，允许比较，并记录所有哈希。

| 退出码 | 含义 |
|---|---|
| 0 | 首次建立基线、比较通过，或显式接受了新基线 |
| 1 | 执行、来源校验或输出校验失败 |
| 2 | 检测到质量或性能回归（参数错误也可能由 argparse 返回 2，查看终端错误） |
| 3 | 运行完成，但因数据/协议/环境不同无法完成可比判断 |

检测到回归仍保留完整报告，方便人工判断取舍；agent 不应为了得到 0 而自行重设基线。

## 稳定输出

默认根目录为 `artifacts/backend-benchmark/public/parallel-8/`；`--workers N` 对应 `parallel-N/`，不同进程数独立建基线。
迁移前的串行基线原样保留在 `current/`、`public/` 下，4 进程三轮基线仍在 `parallel-4/`，不覆盖或删除。
旧 v1/v2 报告仍可比较切分质量，但与新 v3（8 进程、两轮算术平均值）协议的速度不直接比较。
手动指定 `--output` 时仍使用指定目录，混入不同协议会明确报告性能不可比。
文件均为本地生成结果，不纳入 Git。

主报告的稳定路径是 `<输出根目录>/report.json`，每次运行覆盖为最新结果；历次报告保存在 `runs/<run_id>/report.json`。

| 字段 | 内容 |
|---|---|
| `schema_version`, `run_id` | JSON 结构版本与本次运行标识 |
| `backend` | 后端代码指纹、模型 epoch/权重身份/词表大小/通道/层数，以及实际规则参数 |
| `test` | 数据集、句数、进程数、轮数、预热数、评分口径和 F1 公式 |
| `results` | `sentence_accuracy`、`precision`、`recall`、`f1`，均为 0～1 数值 |
| `performance` | 每轮及平均秒数、启动秒数、吞吐、累计计算时间、调用数和延迟分布 |
| `environment` | CPU、Node、ICU、系统和架构 |
| `comparison` | 有基线时才出现：基线 ID、状态、质量/性能差值和回归项 |

主报告版本是 `haodu-benchmark-v1`。报告内比率与性能数值保留六位小数，内部回归比较仍使用原始精度。
`request.json` 保存配置和来源记录，`timings.json` 保留原始计时，`cases.jsonl` 保留逐题答案；这些是查错数据，不另生成文案报告。
基线指针校验报告、配置、原始计时和逐题结果的哈希。旧格式基线仍可读取；改报告格式不需要重跑模型或重设基线。

替代后端或模型实验可以指定 `--backend-dir`、`--model` 和 `--output`；建议单独输出目录，保留正式基线。
此命令与历史阈值子集研究的 `golden:evaluate` 分开，后者不用于标准性能回归。
