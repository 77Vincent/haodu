# Golden：标贝 BZNSYP

自 **2026-10-25** 起，正式 Golden 来源固定为标贝 BZNSYP 的 **10,000 句**。停止从训练/验证语料抽题，停止人工增加、移动切点，也不根据模型预测改写标准答案。

## 唯一正式题目文件

[cases.csv](cases.csv) 保存全部 10,000 行，只有 `text,source` 两列：

- `text` 保留原始文字、标点、`#2` 与 `#3`。仅移除不参与本任务的词级 `#1` 和句末 `#4` 标记；不丢句、不修辞、不修错别字或引号。
- `#3` 是必须命中的边界；`#2` 是可切可不切的边界。
- `source` 保存原始文件行号及六位 ID，可回查官方标注。原始文本的 SHA-256、导入后 CSV 哈希、来源网址与使用限制保存在 [source.json](source.json)。该 JSON 是元数据，不是另一份题集。

题库由 main repo 的评测工具管理，但 CSV 仅安装在本地，已被 `.gitignore` 排除。
`source.json` 保留官方来源、使用限制和固定哈希。代码仓库不再分发这份第三方语料。

新克隆从元数据中的官方来源取得 `000001-010000.txt` 后，在 haodu 根目录执行：

```sh
npm run golden:import -- --source /path/to/000001-010000.txt
```

导入器同时校验原始标注和生成 CSV 的固定 SHA-256；不会改写标签或使用其他版本。
本地已迁入原题库，不需要重新下载。

全量保存与评测适用性分开。文件中的行不意味着通过全部硬规则，也不意味着已逐句确认零错误。当前仅抽查过合规池中的 400 句；不把抽查结论说成全量人工审核。

## 全量后端回归基准（2026-10-29）

日常开发统一用 `npm run golden:benchmark` 同时检验切分能力和推理速度。
**每次固定评测全部 10,000 句**，保留短句、规则不兼容题和已知错标，不应用下方研究子集的筛选。
题面仍去掉 #2/#3 紧邻的 proxy，评分仍为 #3 必切、#2 可选及右双引号等价匹配。
标准答案不作为训练输入；它们是训练方案、权重和后端开发的固定评估标准。

实际后端按自身默认配置运行；固定 8 个进程各处理 1,250 句，分别预热后无缓存测两轮并取算术平均值，轮内并行、轮间串行。
命令、基线比较、稳定 JSON 字段及性能测量范围见 [标准基准](../../docs/backend-benchmark.md)。
下方 `golden:prepare` / `golden:evaluate` 只用于阈值子集研究。

## 12 与 13 阈值并列研究

**12 尚未确定为最终阈值。** 阈值子集研究默认准备与评测 12、13 两组，线上后端继续保持其原有配置。

自 2026-10-26 起采用 `all-annotated-boundaries-v2`。筛选检查原始 #2＋#3 的完整答案，评分仍为 #3 必切、#2 可选。旧版仅检查 #3 的结果保留作历史对照，不代表新标准。

题面准备与合规检查：

1. 找到原始 `#2/#3`，删除其紧邻的连续 proxy：`，。！？；…、：,.!?;:`。按原始字符位置建立映射，再转换到后端使用的 UTF-16 切点偏移。
2. 其余文字、引号与非邻接标点不动。引号左侧的标签保持原位置，不自动外移；评分时按下述规则容许右双引号内外的等价切点。这与另一个 AB teacher 引号归一化课题分开。
3. 去 proxy 后题面为 13～64 个 Unicode 码点。汉字、连续数字、Latin 单词的视觉长度使用实际后端计算，不能把这个码点范围与父片段阈值混为一谈。
4. 使用原始 **#2＋#3 全套切点**检查书名号限制、归一化 token 间隙、词内保护，以及最终片段最多 13 视觉单位。不能先删去 #2，再把合并后的片段用于长度校验。
5. 全部 #2/#3 必须能同时组成一棵合法递归树；每次切分前父片段的视觉长度必须达到本组阈值。只要求存在一种合法顺序，不要求所有切分顺序都合法；不查看模型预测来决定入选。
6. 去重并排除同文异标冲突；不查看模型结果进行筛选。已确认错标 ID `003892`（东｜河疃村）保留在源 CSV，通过元数据排除评分，不另造修订答案。

以当前后端及 Node v25.9.0 / ICU 78.3 校验：

| 阈值 | 机械合规 | 排除已知错标后的评分句数 |
|---|---:|---:|
| 9 | 6,474 | 6,473 |
| 10 | 5,701 | 5,700 |
| 11 | 4,713 | 4,712 |
| 12 | 3,766 | **3,765** |
| 13 | 2,721 | **2,720** |
| 14 | 1,909 | 1,908 |
| 15 | 1,310 | 1,309 |
| 16 | 858 | 858 |

默认 12、13 两组共同题目为 **2,720 句**；9～16 八组共同题目为 **858 句**。全量 CSV 仍为 10,000 句。已知错误可能本来就不合规，因此机械数量与评分数量不一定相差 1。

例如 `墨西哥#2一五二一年#3沦为#2西班牙#2殖民地`，完整答案片段为 3/5/2/3/3，无法在 9～16 阈值下全部切出，现全部排除。仅用 #3 得到的 8/8 不能证明完整标注合规。

新题集不一定是旧题集的子集：完整标注检查会排除无合法切序的题目；按完整答案计算片段长度，也可能纳入以前只按 #3 合并后超过 13 的题目。评分中的 #2 可选性不变，不要求模型输出全部 #2。

评测同时报告各自 base 和共同题目两套结果；横向比较阈值效果时使用共同题目，不能把不同分母的成绩当作阈值收益。规则或分词环境变化时重新生成子集并记录版本、哈希和数量，不静默覆盖历史报告。

## 评分

自 2026-10-26 起采用 `right-double-quote-equivalence-v1`：原标注和预测位于**同一个中文右双引号 `”` 的两侧**时，视为命中同一边界。方向对称，只跨越这一个字符，不跨左引号、其他标点、文字或句子首尾。

例如原标注 `“每日电讯报｜”盘点了……`，预测为 `“每日电讯报”｜盘点了……` 也算命中。若原标注为 #3，既不算错切，也不算漏切。

采用**一对一匹配**：一个预测只能命中一个标注，一个标注也只能接受一个预测。先匹配必切 #3，再匹配可选 #2；同一引号两侧都预测切点、却只有一个原标注时，额外一刀仍算错切，不能把引号单独切出而获得双重计分。逐题 `matches` 保留原标注位置、预测位置、标注级别和是否跨过引号。

- **错切比例**：`未匹配的预测切点数 / 全部预测切点数 = 1 − Precision`。
- **漏切比例**：`未匹配的 #3 数 / 全部 #3 数 = 1 − Recall`。没有切可选 #2 不算漏切；命中其他 #2 不能抵消漏掉的 #3。
- **整句正确**：全部 #3 被匹配，并且没有未匹配的预测切点。

JSON 同时保留切点精确率和必切覆盖率，Markdown 使用错切、漏切比例（均越低越好）。两者采用不同分母，不直接相加。标准 benchmark 另外按约定输出二者调和均值 F1，定义见基准说明。分母为零时输出 `null`，不擅自填成 100%。模型、置信度、后端哈希、Node/ICU 版本及逐题多切/漏切随评测报告保存。

本规则只改变评分匹配，不修改 CSV、题面、原始标签或合规筛选，不把引号内外两处都当作必须切出的答案。原严格位置评分的历史报告保留。`score(..., text=raw)` 启用等价匹配；省略 `text` 的历史调用仍使用严格位置匹配。

## 命令

在 haodu 根目录执行：

```sh
# 不运行模型：全量校验并生成两个研究子集
npm run golden:prepare

# 不运行模型：沿用原有检查命令，自动识别新题库并检查两个阈值
npm run golden:check

# 分别评测 12、13；默认本仓库当前 16,384 词表模型，置信度 0.45
npm run golden:evaluate

# 使用指定导出模型及独立结果目录；先运行 prepare
python3 benchmark/evaluate_golden.py \
  --model /path/to/exported-model.js \
  --inference /path/to/haodu/src/backend/inference.js \
  --output artifacts/bznsyp-golden-all-boundaries-v2/my-model
```

默认准备结果位于 `artifacts/bznsyp-golden-all-boundaries-v2/`，与旧标准分目录保存。`prepared.json` 保留全部题面、proxy 删除位置、各组逐题通过/拒绝原因和规则版本；`summary.json` 保存统计。当前评测结果默认在其 `evaluation-quote-equivalence-v1/` 子目录，避免覆盖原严格位置评分。评测器拒绝旧版准备文件，避免误用仅 #3 合规的题集。评分代码更新也会改变输入哈希，运行新的模型评测前应重新执行 prepare。

复现 9～16 的新标准研究：

```sh
python3 benchmark/prepare_golden.py --thresholds 9 10 11 12 13 14 15 16 \
  --output artifacts/bznsyp-golden-all-boundaries-20261026
python3 benchmark/evaluate_golden.py \
  --prepared artifacts/bznsyp-golden-all-boundaries-20261026/prepared.json \
  --output artifacts/bznsyp-golden-all-boundaries-20261026/full-rerun
```

历史 `training/artifacts/bznsyp-golden-all-boundaries-20261026/` 留在训练仓库，其中的 `report.md` / `report.json` 为 2026-10-26 E6 新标准结果。上述命令在 main 生成新的研究结果，不会覆盖历史记录。`rescore.py` 核验旧预测的题面、标签、模型、后端、置信度及来源哈希，复用仍适用的预测，并补跑新增题目的缺失预测；`reuse-plan.json` 记录每组新增、排除和复用数量。独立按切点集合重算计数，与正式评分函数交叉校验。模型或准备文件变化时须使用新目录，不复用不匹配的缓存。

上段历史 `report.json` 采用严格位置评分。相同预测按右双引号等价规则重计分的历史结果保存在训练仓库的 `training/artifacts/bznsyp-golden-quote-equivalence-20261026/`；该目录的 `rescore.py` 校验原报告和题集哈希，保持各组题目、预测和模型来源完全不变，仅更新评分。`changed-cases.json` 保存所有受影响题目的旧分数、新分数和匹配证据。这不是使用当前工作树后端重新推理。

旧标准的结果作为历史研究记录留在原训练仓库的 `training/artifacts/`，包括 `bznsyp-golden-v1`、`bznsyp-golden-min11-20261026`、`bznsyp-golden-min10-14-20261026`、`bznsyp-golden-min9-16-20261026`，仅供历史复现。它们采用“仅 #3 合规”的筛选，不能直接沿用旧 base 或直接比较新旧百分比。所有产物只保存在本地，不是另一份手工维护的正式题集。

恢复全量 CSV 可使用官方原始标注文本和本目录固定的 `source.json`：

```sh
python3 benchmark/import_bznsyp_golden.py \
  --source /path/to/000001-010000.txt
```

导入器校验原文哈希、10,000 个连续 ID、双行格式以及全部保留文字/标签。官方来源与原始用途限制沿用下载记录，不在本次迁移中改变。

本次没有更改训练任务、模型参数或生产阈值。标贝题目经过多次查看和研究使用，应称固定研究评测集，不宣称从未接触过的独立盲测集。
